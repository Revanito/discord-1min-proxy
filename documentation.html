Discord Bot + FastAPI Proxy for 1min.ai

A self-hosted Discord bot that gives a server access to 1min.ai's multi-model AI subscription, through a small FastAPI proxy that holds the API key and tracks per-thread conversation context. Built as a school project for the September 2026 jury exam.

1. Overview

There is no self-hosted AI assistant yet, so the Discord bot talks directly to 1min.ai via a proxy. The proxy is the only thing that ever sees the 1min.ai API key; the bot only holds its own Discord token and a shared secret to authenticate to the proxy.

What it does

  • Lets any Discord server member chat with a 1min.ai-backed model
  • Keeps conversation context per Discord thread
  • Keeps the real 1min.ai key off the Discord bot entirely

Why a proxy instead of calling 1min.ai directly from the bot

  • Only one process needs the paid API key
  • The proxy can be swapped for a different backend (a future self-hosted assistant) without touching the bot
  • Easier to defend as a design choice in a jury Q&A: separation of concerns, credential isolation

Why not streaming (v1)

  • Discord messages are sent as one block after the full reply anyway
  • Keeps both services simpler for a first working version
  • Documented as a future improvement, see section 12

2. Architecture

Discord server
   |
   | @mention or reply in thread
   v
Discord bot (discord.py) ----HTTP + X-Proxy-Key----> FastAPI proxy ----API-KEY----> api.1min.ai
   ^                                                        |
   |                                                        v
   +----------------- reply text <------------------- conversations.json
                                                        (thread_id -> conversationId)

Both services run as separate Docker containers, managed by a single docker-compose.yml, on one Proxmox LXC. The bot never holds the 1min.ai API key; the proxy never holds the Discord token.

3. 1min.ai API reference

Confirmed from docs.1min.ai:

Item Value
Base URL https://api.1min.ai
Auth header API-KEY: <key>
Create conversation POST /api/conversations
Chat POST /api/chat-with-ai
Reply location in response aiRecord.aiRecordDetail.resultObject[0]

Example chat request body:

{
  "type": "UNIFY_CHAT_WITH_AI",
  "model": "gpt-4o-mini",
  "promptObject": {
    "prompt": "What are the latest developments in AI?",
    "conversationId": "120qae97-d77d-468d-9d78-2e7c0b2bbb98"
  }
}
Streaming (?isStreaming=true, SSE) exists on the 1min.ai side but is not used in v1 - see section 12.

5. FastAPI proxy

POST /v1/chat is the only endpoint the bot calls.

Field Required Notes
thread_id Yes Discord thread/channel id, used as the conversation key
message Yes The user's text
model No Falls back to DEFAULT_MODEL

Request header required on every call: X-Proxy-Key: <PROXY_SHARED_SECRET> (checked by auth.py, returns 401 if missing/wrong).

Logic in main.py:

  1. Look up thread_id in conversations.py.
  2. If not found, call 1min.ai's POST /api/conversations to create one and store the id.
  3. Call POST /api/chat-with-ai with that conversationId and the prompt.
  4. Return {"reply": "..."}.
Errors from 1min.ai (timeout, non-2xx, missing resultObject) are caught in onemin_client.py and re-raised as HTTPException(502, ...), so the bot always gets a clean JSON error instead of a stack trace.

6. Discord bot

Uses discord.py with only the message_content and default intents.

  • @mention the bot in a normal text channel → it creates a thread off that message and treats the mention text as the first prompt.
  • Any further message inside a thread the bot owns (thread.owner_id == client.user.id) is treated as a continuation - no re-mention needed.
  • Shows a typing indicator while waiting on the proxy call.
  • Splits replies over 2000 characters into multiple messages (Discord's hard limit).
  • Optional ALLOWED_GUILD_IDS env var restricts which servers the bot responds in.

7. Configuration (.env)

Copy .env.example to .env and fill in:

ONE_MIN_API_KEY=your_1min_ai_api_key
PROXY_SHARED_SECRET=choose_a_long_random_string
DEFAULT_MODEL=gpt-4o-mini

DISCORD_BOT_TOKEN=your_discord_bot_token
ALLOWED_GUILD_IDS=
Never commit the real .env file - it holds both the 1min.ai key and the Discord token. .gitignore already excludes it.

8. Proxmox LXC deployment

Both containers run via Docker Compose inside a single Debian LXC - no need for two LXCs at this scale.

8.1 LXC setup

  • Template: Debian 12, not Alpine (Docker's official install path targets Debian/Ubuntu cleanly).
  • Enable nesting on the host: pct set <vmid> --features nesting=1,keyctl=1
  • Unprivileged LXC works on modern Proxmox kernels; fall back to privileged only if the storage driver fails.

8.2 Packages inside the LXC

apt update
apt install -y ca-certificates curl gnupg git

# Docker's official repo + engine
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  > /etc/apt/sources.list.d/docker.list
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

9. Running it

git clone <this repo> /opt/discord-1min-proxy
cd /opt/discord-1min-proxy
cp .env.example .env

docker compose logs -f

10. Testing procedure

  1. docker compose up --build - both containers start without errors.
  2. curl -X POST http://localhost:8000/v1/chat \
  -H "X-Proxy-Key: $PROXY_SHARED_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"thread_id":"test1","message":"Say hi in 5 words"}'
    returns a JSON reply from 1min.ai.
  3. Same request without X-Proxy-Key returns 401.
  4. In Discord, @mention the bot in a channel → it creates a thread and replies.
  5. Reply inside that thread without mentioning → bot replies with context retained (ask something that depends on the prior message).
  6. Ask for a long reply (>2000 chars) → confirm the bot splits it into multiple messages.

11. Troubleshooting

Bot never responds

  • Check the bot has the Message Content Intent enabled in the Discord Developer Portal.
  • Check docker compose logs bot for connection errors.
  • If ALLOWED_GUILD_IDS is set, confirm the server's id is in the list.

401 from the proxy

  • Confirm PROXY_SHARED_SECRET matches exactly between bot and proxy environments.

502 from the proxy

  • Check ONE_MIN_API_KEY is valid and the subscription is active.
  • Check docker compose logs proxy for the underlying 1min.ai error message.

Docker fails to start inside the LXC

  • Confirm nesting=1 and keyctl=1 are set on the LXC (pct config <vmid>).
  • If overlay2 storage errors persist, switch the LXC to privileged.

12. Future improvements

  • Streaming replies (SSE from 1min.ai) edited progressively into the Discord message.
  • Swap the proxy's backend for a self-hosted assistant once one exists, without changing the bot.
  • Slash command (/ask) for quick one-off questions outside of threads.
  • Per-user or per-guild model selection instead of a single DEFAULT_MODEL.
